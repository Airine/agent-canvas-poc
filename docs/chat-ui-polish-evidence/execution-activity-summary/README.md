# 执行短句验收

收起执行行现在包含一句由工具与当前状态生成的进度说明，不再只显示泛化的“执行中/思考中”。

## 规则

- 当前工具优先：读取/修改/写入/搜索/查找与本地常见测试/构建命令生成对应动作；并明确并发数。
- 工具完成后模型仍运行：`已完成/已查看/已修改…，正在梳理结果`。说明按调用次数聚合，不把同一文件统计成多个。
- 待批准、失败、拒绝、取消、未知结果和会话未就绪优先；不呈现为进行中或成功。
- 本地确定性分类，不调用模型；不引用思考、输出或复杂 shell 正文。命令结束不等于测试通过，Canvas 入队/派生不等于消费/就绪。
- 路径只显示经过边界/敏感检查的短文件名，匹配全文脱敏模式的内容回退为类别说明。

## 验证

- 新增 6 项单元：活跃动作、并发、完成回顾、审批/失败/未确认、控制字符/敏感参数、Canvas 语义。
- 新增 1 项浏览器：读取 → 思考梳理 → 修改 → 等待批准 → 失败，检查短句 DOM 稳定、草稿 DOM 保留、不自动展开、无 API 写请求。
- 最终全量结果见 `verification.json`。浏览器仍使用 HTTP/WS fixtures，不代表真实模型/工具执行。
- [桌面短句](activity-thinking.png)与 [390px 状态](activity-mobile.png)均由 Chrome fixture 截图；两张均已在 PI-Desktop 内置浏览器目视确认。
- 发现窄屏失败短句与失败徽标有冗余，已改为短句 `修改 view.ts未成功` ＋独立“1 个工具失败”；修正后整套回归重跑通过。

只改前端展示，可热更新；未重启服务、调用模型、执行真实工具或操作用户会话，也没有提交推送。
