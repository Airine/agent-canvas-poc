# 辅助审批策略 v2：隔离证据

## 改动与边界

旧策略把所有引号、命令链和 Canvas 工具几乎都提前转人工。新策略对支持的完整可见操作进行有界语法/效果检查后，真正调用独立 AI；只有明确 approve/low 可继续提交。删除、凭据、外传、动态/未知执行等仍由规则拦截。详见 `docs/card-views-and-approvals.md`。

## 真实独立模型审查

`real-review.json` 来自 `deepseek/deepseek-flash` 的真实无工具审查，不是 fixture 模型输出：
- 合成临时项目中的 `sample.json`；拟执行命令只读文件并输出 name/count。
- `ApprovalEngine` 使用实际规则和真实 `reviewApproval`，审查调用 1 次，结果 approve/low。
- 最终授权提交端是测试替身，捕获 1 次提交；**没有执行命令，没有调用真实 e 审批端，也没有证明新的日常工具已执行成功**。审计中的“提交到 e”是引擎的标准文案，本测试只能证明调用了提交端。
- 没有访问用户 pending 请求/历史、发送用户会话提示或重启日常服务；不修改全局模型/认证。

## 回归范围

单测覆盖引号、管道、逻辑/换行/CRLF/注释边界、危险尾命令、包装器/重定向/未闭合语法、Node 模块/加载器/动态路径/隐藏文件/链接、Canvas 契约/敏感内容、实际规则到 AI 调用、重复 observe 去重、路径/native/cwd/epoch/模式/能力变化、人工覆盖及 peer 不替代人类任务。浏览器使用 HTTP/WS fixtures 检查“未调用 AI”与“已审查”的区别、旧 API 提示、待 e 确认和草稿 DOM 稳定。

最终全量结果记录在 `verification.json`；不把历史版本的工具执行验收算作本次结果。
