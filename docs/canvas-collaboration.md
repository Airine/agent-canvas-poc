# Canvas 跨 Agent 协作

## 使用方式

1. 在 Agent 昵称的铅笔旁点击**复制**，得到如 `@"研究员 B"#91d66efe` 的引用。复制失败会提示，不能把失败显示成已复制。
2. 在另一张卡片的输入框输入 `@`，出现同一 Canvas 的其他真实 Agent，排除自己。可按昵称或 hash 搜索，用方向键与 Enter/Tab 选择，Esc 关闭；中文输入法组合期间不会误选或发送。
3. 写清任务，例如“请读取 @… 的结果，核对后决定是否向它追问”。**选择引用不会自动发消息**；Agent 根据上下文决定读取、发送或不操作。
4. 工具执行遵守当前会话权限。默认手动模式需要批准；辅助模式对这些新工具仍转人工；只有用户明确启用当前会话 Full Access 才按既有规则自动批准。没有新增全局权限。
5. 发生真实读取或发送后，画布出现独立的通信边。点击状态标签查看来源、方向、内容、时间、消费状态和产物摘要。

## Agent 能调用的工具

| 工具 | 能力 | 边界 |
| --- | --- | --- |
| `canvas_agents` | 列出同画布其他 Agent、引用、生命周期、最近回复 ID 和最近 20 个产物元数据 | 不列自己，不跨画布，不自动发送 |
| `canvas_read` | 读取指定公开文本产物；也可读取已完成的助手文本回复，省略 ID 时取最新回复 | 不读任意文件路径、思考块、工具日志或远程内容；截断明确标记 |
| `canvas_publish` | 发布有 ID、来源、时间和 SHA-256 的不可变文本产物 | ≤12000 JS 字符单位且 UTF-8 ≤16 KiB；不是文件上传 |
| `canvas_send` | 向同画布另一 Agent 的 Canvas 待发队列发送文本消息 | 不 Steer、不中断、不创建会话、不唤醒停止目标、不自动解冻暂停队列 |

这些是 Canvas 显式装载给 Pi 的受管扩展工具，配套版本化的独立 Skill，**不依赖机器上全局 skill/MCP/CLI 的自动发现**。没有另建公开远程发送 API。

## 独立 Skill、共享契约与加载确认

- `skills/canvas-collaboration/SKILL.md` 是随仓库发布的独立 Skill（版本 1），负责教会 Agent 何时读取、发送或不操作。worker 显式加载该文件，扩展同时把相同版本正文绑定到每轮系统指令；这不等于模型必然遵守，安全约束仍由代码执行。
- `app/shared/collaboration-protocol.mjs` 是四个工具的唯一契约：参数与结果 schema、权限要求、顺序执行、大小/频率/链预算和稳定错误码。Pi TypeBox 定义、API 校验及回执结果校验共用它，不维护第二套发送逻辑。
- 资源包 manifest 包含协议/扩展/Skill 版本、契约与 Skill 摘要、工具列表和 bundle 摘要。API、worker 和扩展逐层比对；必须观察到 Skill 已发现、4 个工具实际启用、系统指令绑定模式及私有 hello/welcome 成功，才能显示“已验证”。旧 `collaborationAvailable` 布尔值不能替代握手。
- 点击既有的“会话状态与上下文”状态球，在“Canvas 协作能力”中查看验证中、已验证、不可用或版本不匹配，以及版本、工具数量和摘要。断线或停止后只展示历史信息，不把缓存当当前权限。

只读检查资源包（不会创建会话、发送消息，也不证明某个运行中的 Pi 已加载）：

```bash
cd app
npm run collaboration:inspect -- --manifest
npm run collaboration:inspect -- --schema
npm run collaboration:inspect -- --skill
```

服务错误统一包含 `code`、`message` 与 `retryable:false`。参数、权限、目标、冲突或限额错误需要修正原因；`OUTCOME_UNKNOWN` 必须核对既有记录，不能换 ID 自动重发。e 的审批拒绝仍走原有审批通道，不伪装成工具成功。Skill、昵称与环境变量都不是权限凭据。

## 身份与引用

昵称只负责描述；稳定 hash 来自 workspace/node 身份，不由昵称决定。普通标题仍仅在重名时显示短后缀，但复制与补全始终带完整 hash。改名后旧引用仍按 hash 指向同一 Agent；找不到或存在歧义时拒绝，不按相近名字猜测。特殊字符使用 JSON 引号转义。

通信工具请求来自独立 Pi 进程的私有描述符，经 worker 的父子 IPC 进入 Canvas。子命令不能继承该描述符。服务端对照同 native 的 e 快照，核验**已批准、正在执行、名称和完整参数一致**的工具；不接受正文或浏览器声明的发送方。

接收消息中的 Agent 来源先由真实 action applied 与消息观察事件关联。历史重放改变 e 消息 ID 时，只能从之前保存的**同 native、时间、完整内容摘要**唯一匹配恢复，且重放观察本身需来自可信适配器。正文写“我是 Agent A”不会获得 A 身份；没有旧证据或存在歧义的历史保持未知。这里是本地受管通道身份关联，不是多租户安全沙箱，也不是操作系统级的不同用户认证。

## 队列、状态与循环限制

- 空闲且已就绪的目标可按批准后的发送进入队列并依次执行；正在执行或等待审批时排队，不影响当前轮。
- 目标停止、用户暂停、重启暂停或结果未知时，不自动恢复。**恢复会话与恢复待发是两个明确动作**。
- “待发／已暂停”只是保存成功，“等待消费确认”不是已收到；只有 e 观察到精确输入元组才显示“已消费”。这仍不代表 Agent 采纳要求或完成任务。
- 其他 Agent 的文本是任务数据，不是用户授权。接收者可以依据任务边界拒绝执行；不强制自动答复或来回确认。
- 同一 native/toolCallId 回执防重复，参数变化拒绝复用。中断或超时的未确认操作不自动重放。
- 来源为 Agent 的待发可删除、排序、暂停或明确立即发送，但不可修改正文后继续冒充原发送方；需要修改时以自己身份新发。
- 每 Agent 每分钟最多 10 次发送、每轮最多 8 次；Agent 消息链最多 4 跳、16 条。上限来自可信输入关联，不相信正文声称“新的人类任务”。
- 每 Agent 最多 100 个文本产物、服务最多 1000 个产物；通信历史上限 5000 条、回执 10000 项。达到上限明确拒绝，不静默删除历史。

## 连线表示什么

`communication` 是独立于旧 `strong/weak/error` 的边类型。箭头表示**操作发起方 → 目标**；同一对 Agent 的读取与发送分道，双向关系也分开，避免标签覆盖。标签显示次数和最近状态，详情展示该关系最近 50 条记录，不混入两端其他日志。

只有提及、列目录、待审批或被拒绝的工具调用，不会生成虚构通信关系。发送在实际入队时形成记录，后续跟随队列显示暂停、消费、拒绝、移除或未知。读取在取得结果时记录确切产物/回复 ID 与完整文本摘要。

这不是 DAG 调度器，不自动分配任务、启动新 Agent、合并 Git 或突破审批。

## 启用与兼容性

前端复制和补全可经 Vite 热更新生效。**API 和已运行的 Pi 不会热注入新工具**：需要在任务可以安全停止时重启 API，再明确恢复所需会话。不要为加载功能中断正在使用的会话。

Canvas 在每次启动的自有 generation 目录生成适配器副本，仅扩展原有审批工具名单并重定位导入。ADE checkout 和全局 Pi 安装、默认模型、认证都不修改。这是当前 SDK 缺少正式自定义工具审批接口时的过渡适配；已知审批锚点不兼容时停用协作并回退原适配器，普通聊天继续，但绝不静默降级为无审批的协作。旧 API 未提供 manifest、版本不符、握手超时、资源变化或私有通道断开，也不会授予协作能力。

早期 HTTP/WS 验证使用独立项目、数据目录和 3331/5212 端口；版本包验收直接在唯一临时目录启动受管 worker，不占用日常端口。日常 3319/5199 服务未被本次重启，已有进程仍需安全更新后才能加载新版本。

运行数据不属于源码：API 编译与 ESLint 明确排除 `api/data/`、`dist-api/`，API TypeScript 启用 `noEmitOnError`。不能让 generation 中的适配器副本进入源码编译，更不能为通过检查删除会话历史。

### 显式重跑真实冒烟测试

```bash
cd app
CANVAS_COLLAB_ACCEPTANCE=1 node --import tsx test/manual/real-collaboration.mjs
```

它会消耗实际模型额度，只在唯一临时目录创建测试会话，并仅批准隔离测试里的四类 Canvas 工具。证据目录输出到终端；退出时停止自己的会话，不重启日常服务。默认 `npm test` 和浏览器夹具不执行这个脚本。
